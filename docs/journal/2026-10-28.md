## Problems → cause → fix

1. macOS ARM64 build included Linux DRM headers → V3D guarded by ISA alone → require both
   `__aarch64__` and `__linux__` in `gpu.c` / `gpu_v3d.c`.
2. Darwin `rusage` fields hidden with POSIX feature macros, and RSS units differ → enable
   `_DARWIN_C_SOURCE` for the CLI and divide Darwin bytes by 1024², not Linux's KiB divisor.
3. `xcrun --find metal` fails → offline Metal tools unavailable → compile shader source through
   `MTLDevice newLibraryWithSource`; no full-Xcode or system developer-directory change needed.
4. Initial C object had a newer deployment target than the link target → apply macOS 13 target
   consistently to C and Objective-C; objects now depend on the build Makefile for flag changes.
5. First root-Makefile edit changed Linux's implicit default → explicitly retain `all` on Linux,
   choose `metal` only on Darwin.
6. GitHub CLI missing / no auth → installed `gh` 2.103.3 via Homebrew; `gh auth status` reports
   no signed-in hosts initially. The user completed GitHub device authorization, signing in as
   `Optimizer077`. No credentials or device codes are stored in the repository.
7. Two independent-looking local git config changes briefly contended on `.git/config.lock` →
   retried branch tracking removal sequentially; it succeeded. No lock file forcibly removed.
8. System Python lacks NumPy → created ignored project-local `.venv`, installed NumPy 2.4.6,
   and ran the inherited synthetic CPU regression suite there. Metal tests remain dependency-free.
9. Initial push of foundation commit `be1fed0` rejected by GitHub because the OAuth token lacks
   `workflow` scope required for `.github/workflows/macos.yml`. Requested an auth refresh for
   that scope; the user approved the device authorization and the retry succeeded. No history
   rewritten or workflow removed. `main` now tracks `origin/main` in the new private repository.

### Implementation

- Added `engine/macos/Makefile` native builds for the original no-SDOT CPU kernels, Apple SDOT
  CPU kernels, and an opt-in Metal hybrid. Existing public C API / `ops.h` semantics remain unchanged.
- Ported the fast pool's Linux-only sleep/affinity behavior to a macOS condition-variable idle

## Follow-up session — persistent state / single-submit GPU MLP

User approved further work, then requested the current tables and an immediate push to GitHub.

### Implemented

- Optional `NM_METAL_MLP=1`: six GPU dispatches in one command buffer for input quantization,
  gate/up, exact SiLU*up, intermediate quantization and down. One host wait instead of three,
  no CPU gate/up/activation copies. Eligible Q4K MLPs override the generic offload cutoff only
  when this explicit flag is enabled. Unsupported MLP shapes/dtypes retain their previous path.
- Optional `NM_METAL_RECURRENCE=1`: allocate mutable recurrent state as pool-owned shared Metal
  buffers. CPU state pointers refer to the same allocations; no mirrored state upload/download
  each token. Exact chunk-major GPU recurrence, speculative rollback logs, pending updates and
  replay. Commands finish before CPU reset/save/load/rewind. Pool allocation/free hooks also
  preserve the scalar and native CPU paths; model pools are initialized before state allocation.
- Experimental `packed4` kernel: reuse weights across four token vectors while preserving each
  result's accumulation order. It passed exactness but did not improve the first prefill sweep;
  not made default. It is not a SIMD-group matrix GEMM implementation.
- Added `make test-graphs`, `tools/check_graphs_macos.py`, explicit per-configuration feature
  flags in the benchmark recorder, GPU-work counter gates, stronger state-byte checks and CI
  compile targets for the graph test tools. Architecture/results: `docs/METAL_GRAPHS.md`.

### Evidence and measured decisions

- `bench/results/metal/graph-tuning-20261028T064031.568756Z.json`: feature isolation.
- `bench/results/metal/tile-tuning-20261028T064222.952653Z.json`: MLP grouping / tile tuning;
  negative variants retained, no cherry-picking.
- `bench/results/metal/graph-final-20261028T064355.952875Z.json`: 45 valid/exact full-model runs,
  five configurations x three prompts x three rounds, 128 IDs / 127 timed steps. All last-prefill
  logits and generated IDs match CPU. Same M2 Pro, official model/hash, fp32 KV and warmup protocol.

Median decode tok/s (prose64 / chat36 / repeated prose512):
