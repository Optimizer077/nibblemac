## Problems → cause → fix

1. macOS ARM64 build included Linux DRM headers → V3D guarded by ISA alone → require both
   `__aarch64__` and `__linux__` in `gpu.c` / `gpu_v3d.c`.
2. Darwin `rusage` fields hidden with POSIX feature macros, and RSS units differ → enable
   `_DARWIN_C_SOURCE` for the CLI and divide Darwin bytes by 1024², not Linux's KiB divisor.
3. `xcrun --find metal` fails → offline Metal tools unavailable → compile shader source through
   `MTLDevice newLibraryWithSource`; no full-Xcode or system developer-directory change needed.
4. Initial C object had a newer deployment target than the link target → apply macOS 13 target
   consistently to C and Objective-C; objects now depend on the build Makefile for flag changes.
5. First root-Makefile edit changed Linux's implicit default → explicitly retain `all` on Linux,
   choose `metal` only on Darwin.
6. GitHub CLI missing / no auth → installed `gh` 2.103.3 via Homebrew; `gh auth status` reports
   no signed-in hosts initially. The user completed GitHub device authorization, signing in as
   `Optimizer077`. No credentials or device codes are stored in the repository.
7. Two independent-looking local git config changes briefly contended on `.git/config.lock` →
   retried branch tracking removal sequentially; it succeeded. No lock file forcibly removed.
8. System Python lacks NumPy → created ignored project-local `.venv`, installed NumPy 2.4.6,
   and ran the inherited synthetic CPU regression suite there. Metal tests remain dependency-free.
9. Initial push of foundation commit `be1fed0` rejected by GitHub because the OAuth token lacks
   `workflow` scope required for `.github/workflows/macos.yml`. Requested an auth refresh for
   that scope; the user approved the device authorization and the retry succeeded. No history
   rewritten or workflow removed. `main` now tracks `origin/main` in the new private repository.

## Follow-up session — real inference and measured optimization

User requested optimization, real benchmarks, tokens/sec, and full details. Repository visibility
was changed to public at the user's explicit request and verified through GitHub.

### Implementation

- Added `engine/macos/Makefile` native builds for the original no-SDOT CPU kernels, Apple SDOT
  CPU kernels, and an opt-in Metal hybrid. Existing public C API / `ops.h` semantics remain unchanged.
- Ported the fast pool's Linux-only sleep/affinity behavior to a macOS condition-variable idle
  path with worker QoS. Retained generation-counter publication and independent-row/head splits.
- Used Apple integer dot-product instructions for Q4/Q4K/Q8; retained an explicit `NM_NO_DOTPROD`
  build for A/B comparison. Integer reductions are exact; scale/correction rounding is unchanged.
- Added Metal Q4K/A8 inference with the exact upstream activation quantizer and FMA order. Added
  three kernel mappings and a lossless 32-row coalesced code layout. GPU cache is per-context,
  immutable and bounded; no silent device-error fallback. Other dtypes and non-matmul ops remain CPU.
- Selected a 64 MiB offload cutoff after broad offload was much slower. The measured default Metal
  variant is `packed`. This does not make it faster than CPU; the report explicitly recommends CPU.
- Added pinned checkpoint download with resume and official LFS SHA-256 verification, local model
  conversion, exact-output-gated/locked real-model benchmark tooling, quality/state gates, dependency
  pins, native backend CI cross-compiles and detailed results at `docs/MAC_BENCHMARKS.md`.

### Decision / remaining work

Recommend CPU SDOT with six threads for this measured 0.8B workload. Keep speculation optional,
because the repeated-prose win does not transfer to this chat prompt. Keep hybrid Metal opt-in:
31–35% faster than its first implementation is progress, but still below the CPU baseline.
Next: full GPU-resident activations/state, larger/fused command encoding and tiled prefill GEMM,
then identical quality gates and standard-runtime comparisons. No Pi changes or model publication.
